# Аудит Rufox 0.1.0

**Дата:** 2026-11-18

**Стенд:** Debian 13 (aarch64), GTK4/libadwaita, Meson, AppImage

**Область проверки:** ядро записи, GUI/CLI, privileged helper, пакетирование и регрессионные тесты.

Этот документ заменяет обзор неполного ZIP-архива от 2026-10-25. Он описывает текущее дерево репозитория, а не состояние того архива.

## Что исправлено перед релизом

### Целостность записи

- Очистка старой разметки покрывает primary и backup GPT, включая носители с секторами 512 и 4096 байт.
- DD-запись очищает старую разметку до копирования и останавливается, если очистка не удалась.
- Короткое чтение и преждевременный EOF исходного образа считаются ошибкой, а не успешным концом записи.
- Ошибки финального `fsync()`/`fdatasync()` и сброса буферов перед проверкой больше не скрываются. Для обычных файлов допускаются только ожидаемые `EINVAL`/`ENOTTY` от `BLKFLSBUF`.
- Добавлены регрессионные тесты очистки GPT, короткого чтения, DD round-trip, успешной проверки и обнаружения намеренного повреждения.

### GUI и жизненный цикл операций

- Исправлена утечка `GSubprocessLauncher` и ослаблены гонки при доставке progress/log/result из worker-потока.
- Новый cancel token создаётся до каждой операции, поэтому повторный запуск не наследует старую отмену.
- Путь к helper разрешается через `RUFOX_HELPER` и `APPDIR`; код возврата, stderr и длительность helper передаются вызывающей стороне.
- Аргументы `--iso`, `--device`, `--filesystem` и `--dry-run` действительно применяются при создании окна.
- Hotplug обновляет список при изменении состава, размера или sector size устройств, а не только их количества.
- Ссылки About, desktop metadata и PolicyKit указывают на Rufox; desktop-файл не объявляет неподдерживаемое открытие файлов через MIME/`%f`.

### Честные границы функциональности

- Windows To Go не реализован. Capability API возвращает `false`, а оркестратор отклоняет `RFX_IMOP_WIN_TO_GO` до записи с `ERR_NOT_SUPPORTED`.
- Сжатые образы необходимо распаковать перед записью.
- Исправлен сломанный вывод CLI для имён разделов и обновлены примеры CLI: `info` и `hash` принимают путь через `-i`.

### Поставка

- Проект версионирован как Rufox 0.1.0; production-сборка использует release buildtype.
- Добавлены полный текст GPL-3.0, AppStream metadata, desktop file, scalable/raster icons, compiled GSettings schema и единый `.gitignore`.
- AppImage содержит GUI, CLI, helper и runtime-библиотеки. `AppRun` настраивает bundled environment, GTK hooks и выбор GUI/CLI.
- Privileged helper имеет wrapper, восстанавливающий пути к библиотекам после очистки environment утилитой `pkexec`.
- GitHub Actions собирает и тестирует x86_64 и aarch64 на Ubuntu 22.04, создаёт SHA-256 и публикует четыре файла в Release для тегов `v*`.

## Проверки на Debian 13

- Полная сборка GUI, CLI, helper и unit-тестов завершается успешно.
- Unit suite с ISO fixture проходит без ошибок; fixture включает проверки ISO scanning.
- Упакованный AppImage проходит `list`, `info`, `hash` и `--help`.
- DD-запись во временный файл с `--verify` проходит; записанная область побайтово совпадает с исходником по SHA-256.
- GUI из AppImage работает под Xvfb без критических runtime-ошибок.
- Бинарники AppDir не имеют неразрешённых динамических зависимостей; helper и его wrapper присутствуют и исполняемы.

Во время тестов использовались только временные файловые образы. Реальные USB-устройства не затрагивались.

## Оставшиеся ограничения и следующие задачи

1. **Physical-hardware coverage.** Нужна матрица реальных USB-накопителей, ISO Windows/Linux и сценариев BIOS/UEFI. Файловые тесты не доказывают совместимость со всеми контроллерами.
2. **Windows To Go.** Требуется полноценная реализация WIM apply, ESP/BCD и соответствующие тесты; сейчас режим сознательно отключён.
3. **Compressed images.** Потоковая декомпрессия gzip/xz/zstd и связанные форматы ещё не реализованы.
4. **Отмена privileged helper.** При отмене операции стоит дополнительно проверять и завершать весь process group/root child, чтобы дочерние команды не продолжали работу после закрытия GUI.
5. **PolicyKit в AppImage.** AppImage не устанавливает системную политику; для GUI-записи на блочное устройство нужен рабочий `pkexec` и authentication agent в desktop session.
6. **Дальше по аудиту.** Старые замечания о 4Kn CHS-геометрии, fingerprinting MBR, канонизации `/proc/mounts`, локализации и crash handler остаются кандидатами для отдельного углублённого прохода; они не должны считаться закрытыми без отдельных тестов.

## Вывод

Релизный контур теперь воспроизводим: исходники собираются, регрессии критичных путей записи покрыты тестами, AppImage запускается, а ограничения явно указаны. Это не заменяет испытания на физических USB-устройствах и не превращает неподдерживаемые режимы в работающие.
